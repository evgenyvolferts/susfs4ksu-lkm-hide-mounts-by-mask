# SUSFS4KSU-for-LKM Hide Mounts by Mask

[English](README.md)

Вспомогательный **модуль KernelSU Next** для **[SUSFS4KSU-for-LKM](https://github.com/inforcqb/susfs4ksu-for-lkm)**. Он сопоставляет записи `/proc/self/mountinfo` с настраиваемыми масками путей и регистрирует соответствующие **точки монтирования** для скрытия через `/proc/susfs_hide_mounts`.

Модуль предназначен для реализации SUSFS в виде **загружаемого модуля ядра (LKM)**. Если SUSFS встроен непосредственно в ядро и монтирования уже корректно скрываются, такое дополнение обычно не требуется. Модуль не устанавливает и не загружает LKM.

## Требования

- **KernelSU Next v3.4.2 build 33442-6 или новее** (минимальная поддерживаемая версия).
- **SUSFS4KSU-for-LKM** с работающим управляющим интерфейсом `/proc/susfs_hide_mounts`.

## Назначение и принцип работы

При использовании реализации LKM некоторые bind-монтирования могут оставаться видимыми в `mountinfo`, даже если включены штатные механизмы скрытия SUSFS и настройки KernelSU `try_umount`. Например:

```text
/adb/modules/zygisk_vector/bin/dex2oat64 -> /apex/com.android.art/bin/dex2oat64
/adb/rvhc/youtube-morphe-jhc.apk         -> /data/app/.../base.apk
/adb/rvhc/empty                          -> /product/app/YouTube
```

В этих записях путь `/adb/...` находится в поле **root** (столбец 4 `mountinfo`), а не в поле точки назначения (столбец 5). Префикс `/adb/` в `/proc/susfs_hide_mounts` не выбирает такие монтирования по полю `root`. Поэтому модуль сопоставляет поля `mountinfo` с масками из конфигурации, извлекает **фактическую точку назначения** и регистрирует её через интерфейс скрытия монтирований SUSFS4KSU-for-LKM. В примере конфигурации также учтён временный `tmpfs` модуля AdGuard Certificate.

Интерфейс скрытия монтирований предоставляется **SUSFS4KSU-for-LKM**, непосредственно механизмом **`susfs_guard_lkm`**. Это дополнение не устанавливает сам компонент.

Модуль **скрывает записи о монтированиях, но ничего не размонтирует**. Скрипты и файлы SUSFS4KSU, Zygisk Vector, YouTube Morphe и AdGuard Certificate не изменяются.

## WebUI и конфигурация

**WebUI** модуля доступен в KernelSU Next Manager. Интерфейс наследует светлую/тёмную тему системы и по возможности использует цвета Material You менеджера. В автономном редакторе предусмотрены команды **Reload**, **Save**, **Save & scan**, **Scan now** и **Refresh**.

ID модуля KernelSU Next — `susfs4ksu-lkm-hide-mounts-by-mask`. Редактируемая конфигурация хранится отдельно от модуля:

```text
/data/adb/susfs4ksu-lkm-hide-mounts-by-mask/rules.conf
```

При первой установке она создаётся из [`rules.example.conf`](rules.example.conf). При обновлениях пользовательские настройки сохраняются. При сохранении проверяется синтаксис, файл заменяется атомарно, а предыдущая версия сохраняется как `rules.conf.bak`.

## Синтаксис масок

Каждая непустая строка без комментария содержит `FIELD|GLOB|FSTYPE`:

```ini
# FIELD|GLOB|FSTYPE
root|/adb/*|*
target|/data/local/tmp/adg-ca-copy|tmpfs
```

- `root` соответствует столбцу 4 `mountinfo`, `target` — столбцу 5.
- `GLOB` сопоставляется с полным путём и поддерживает маски `*` и `?`. Квадратные скобки, пробелы и обратные слеши не поддерживаются.
- `FSTYPE` соответствует типу файловой системы после ` - ` либо `*` для любого типа.
- Пустые строки и строки, начинающиеся с `#` (включая комментарии с отступами), игнорируются.
- При совпадении регистрируется **точка монтирования**, а не `root`. Точки с экранированными ядром символами пропускаются.

Маски должны быть достаточно узкими, чтобы не скрывать посторонние монтирования.

### Удаление правил

**При добавлении и сканировании новые точки регистрируются сразу; удаление маски из конфигурации не отменяет ранее зарегистрированные точки в текущей загрузке.** Удалённые маски учитываются при следующей перезагрузке: LKM начинает с новой таблицей runtime-правил, а наш модуль регистрирует только точки, соответствующие текущей конфигурации. Другие компоненты при этом могут независимо зарегистрировать те же точки.

Хотя `/proc/susfs_hide_mounts` поддерживает команду `del`, список правил общий и не содержит сведений о модуле-владельце. Поэтому этот модуль намеренно **не выполняет автоматически** `del`, `set`, `reset` и `clear`: такие операции могут затронуть правила другого компонента. Удалённая маска не гарантирует немедленного восстановления видимости уже помеченных монтирований.

## Установка и обновления

ZIP релиза устанавливается средствами **KernelSU Next Manager**. Управление модулем, его включение, отключение, обновление и удаление выполняются стандартными средствами KernelSU Next Manager.

При загрузке KernelSU Next выполняет собственный `service.sh` этого модуля; штатные скрипты SUSFS4KSU не изменяются. Элемент **Action** в менеджере запускает повторное сканирование вручную. При обновлениях файла правил не касаются, поскольку он хранится отдельно от каталога установленного модуля.

## Запуск и диагностика

До первой разблокировки пользователя (определяется по `sys.user.0.ce_available=true`) модуль сканирует монтирования каждые 10 секунд. Затем в течение примерно 2 минут сканирование выполняется каждые 2 секунды, после чего процесс завершается. Постоянно работающий фоновый сервис не создаётся. Определение разблокировки проверено на Pixel; на других устройствах поведение может отличаться.

Монтирования, появившиеся после завершения сканирования, обрабатываются через элемент **Action** в менеджере либо команду **Scan now** в WebUI.

Для диагностики с правами root:

```sh
cat /proc/susfs_hide_mounts
cat /data/adb/susfs4ksu-lkm-hide-mounts-by-mask/guard.log
sh /data/adb/modules/susfs4ksu-lkm-hide-mounts-by-mask/bin/guard.sh --once
```

Скрытие монтирований не гарантирует прохождения проверок root или целостности. Сами монтирования остаются на месте. Для работы необходим функционирующий интерфейс `/proc/susfs_hide_mounts`.

## Удаление

Модуль отключается или удаляется средствами KernelSU Next Manager. Каталог `/data/adb/susfs4ksu-lkm-hide-mounts-by-mask/` намеренно сохраняется для повторной установки с прежними настройками; при отсутствии необходимости его можно удалить отдельно. Отключение модуля не отменяет немедленно правила, уже зарегистрированные на стороне ядра в текущей загрузке.
